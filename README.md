## Study workflow

1. **Solve** a problem on LeetCode and let LeetSync save the solution.
2. **Understand** the approach: record its intuition, time complexity, and space complexity in `notes.md`.
3. **Recall** the solution: fill in the `Front` and `Back` fields and review it in Anki.

## Anki flashcards

<details>
<summary><strong>Sync directly with Anki</strong></summary>

Start Anki with the AnkiConnect add-on installed, then run:

```bash
python3 scripts/sync_anki.py
```

Notes are added to the **LeetCode** deck. Synchronization runs from repository
notes to Anki: answers edited in Anki are replaced by the contents of `notes.md`.
This script uses only the Python standard library.

</details>

<details>
<summary><strong>Export an Anki package</strong></summary>

```bash
python3 -m pip install -r requirements.txt
python3 scripts/generate_anki.py
```

Import the generated **LeetCode_Deck.apkg** into Anki. The package uses the
**LeetCode Algorithms** deck and stable note identifiers for answer updates.

</details>

Both methods skip incomplete flashcards and display Markdown as plain text.
They use separate decks and notes; choose the workflow you prefer.
The question identifies a flashcard: changing **Front** creates a new note,
while changing **Back** updates its answer.

## Automation

Pushes affecting `solutions/**` on the **test** branch trigger GitHub Actions.

| Stage | Result |
| --- | --- |
| Organize | Move each problem into its category and pattern; create missing notes. |
| Preserve results | Create a separate commit and record the original LeetSync message in `.leetsync.json`. |
| Refresh | Rebuild the solution index and create an `Update README` commit. |
| Publish | Push the generated commits after a successful run. |

<details>
<summary><strong>Run locally & repository conventions</strong></summary>

```bash
python3 scripts/organizer.py
```

Configure Git's `user.name` and `user.email` first, and commit incoming
solutions before running the organizer. The script creates local commits;
it does not push them.

- Problem folders follow `<category>/<pattern>/<id>-<slug>/`.
- Unknown problems go to `Algorithm/Uncategorized`.
- Existing notes are preserved; conflicting notes require a manual merge.
- Unrelated staged changes are excluded from generated commits.
- Errors are reported per problem. A failed run prevents the workflow from pushing.
- The solution index between the HTML table markers is generated automatically.

The extra LeetSync commit changes a metadata file inside the problem folder,
so it appears in that folder's history. If no LeetSync commit is found,
the organizer reports it and keeps the regular commit.

</details>
